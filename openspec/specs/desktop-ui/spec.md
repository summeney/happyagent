# desktop-ui

## Purpose

定义桌面应用的可观察行为：一个常驻的图形界面，让用户在同一会话内持续对话、在多会话间切换，并以流式方式看到 agent 的思考、工具调用与结果。

## Requirements

### Requirement: 桌面应用形态

系统 SHALL 以独立的桌面应用窗口形态提供界面；agent 运行时与工具（含文件读写与 shell 执行）MUST 在本机后台运行，界面与后台之间通过进程内消息通道通信。

#### Scenario: 启动应用

- **WHEN** 用户启动桌面应用
- **THEN** 系统打开一个应用窗口，展示会话列表与当前会话的聊天区，并可立即输入

### Requirement: 同一会话内持续输入交互

界面 SHALL 提供常驻输入框，允许用户在当前会话内不退出、不重启地连续发送多条消息；每条消息 MUST 追加到当前会话的同一 `thread_id` 上。

#### Scenario: 连续追问

- **WHEN** 用户在当前会话发送一条消息并等到回复完成后，再发送第二条消息
- **THEN** 第二条消息与其回复出现在同一会话中，且 agent 的回复参考了第一轮的上下文

#### Scenario: 运行中禁止重复提交

- **WHEN** 当前会话正在生成回复
- **THEN** 界面阻止用户对同一会话重复提交新消息，直至本轮结束

### Requirement: 流式展示运行过程

界面 SHALL 以流式方式增量展示 agent 的运行过程，至少区分并呈现三类内容：AI 文本、工具调用（名称与参数）、工具结果。

#### Scenario: 增量呈现

- **WHEN** agent 正在执行一轮包含工具调用的 ReAct 循环
- **THEN** 界面按发生顺序增量显示 AI 文本、每次工具调用及其结果，而非等到全部结束后一次性显示

### Requirement: 切换会话的界面

界面 SHALL 展示会话列表并支持新建与点击切换；切换后聊天区 MUST 显示目标会话的历史。

#### Scenario: 从列表切换

- **WHEN** 用户点击会话列表中的另一会话
- **THEN** 聊天区替换为该会话的历史消息，输入框后续消息发往该会话

#### Scenario: 新建会话入口

- **WHEN** 用户点击"新建会话"
- **THEN** 界面切换到一个空白会话，会话列表新增该项

### Requirement: run_bash 审批弹窗

当危险操作审批开启时，界面 SHALL 在 agent 请求执行 shell 命令前弹出审批提示，展示待执行命令并提供批准 / 拒绝操作，用户的决定 MUST 驱动后台运行时的继续或跳过。

#### Scenario: 弹窗批准

- **WHEN** 审批开启且 agent 请求执行某命令，用户在弹窗点击"批准"
- **THEN** 后台执行该命令，界面继续流式展示其结果

#### Scenario: 弹窗拒绝

- **WHEN** 审批开启且 agent 请求执行某命令，用户在弹窗点击"拒绝"
- **THEN** 后台跳过该命令，界面展示该命令被拒绝，且本轮循环继续
