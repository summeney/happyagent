## Purpose

定义开发模式的可观察行为：让开发者能一键启动并调试三个进程（主进程、运行时 server、渲染层），前端改动实时热更、可下断点，同时保证生产（打包）路径与行为完全不受影响。

## ADDED Requirements

### Requirement: 开发模式的触发与生产隔离

系统 SHALL 提供一个可显式启用的开发模式，其触发以「渲染层开发服务地址是否由环境提供」为唯一判据，并 MUST 以「应用是否为打包态」作为硬保险：打包态下即便该环境变量存在也 MUST NOT 进入开发模式。开发模式启用的一切行为（热更加载、调试端口、固定端口等）MUST 仅在开发模式生效；未进入开发模式时，系统的可观察行为 MUST 与本次改动前完全一致。

#### Scenario: 打包态永不进入开发模式

- **WHEN** 应用以打包态运行，且环境中意外存在渲染层开发服务地址
- **THEN** 系统仍按生产路径运行（加载打包后的渲染产物、运行时不开放调试端口），不进入开发模式

#### Scenario: 未启用开发模式时生产行为不变

- **WHEN** 以现有的桌面应用启动方式（非开发模式）启动
- **THEN** 窗口加载打包后的渲染产物、运行时使用随机端口且不开放调试端口，行为与本次改动前一致

### Requirement: 渲染层开发态实时反馈

开发模式下，界面 SHALL 从渲染层开发服务地址加载渲染层，使前端源码改动无需整包重建即可实时反映（热更），并在改动生效时尽力保留界面状态；开发态下浏览器开发者工具 MUST 能将运行代码映射回原始 `.vue`/`.ts` 源码（可用的 sourcemap）。生产态下界面 MUST 仍加载打包后的渲染产物。

#### Scenario: 前端改动实时可见

- **WHEN** 开发模式运行中，开发者修改并保存一个渲染层源文件
- **THEN** 界面在无需整包重建、无需手动重启应用的情况下反映该改动

#### Scenario: 前端可断点于源码

- **WHEN** 开发者在浏览器开发者工具或编辑器中打开渲染层代码
- **THEN** 看到的是原始 `.vue`/`.ts` 源码而非打包后的产物，并可在其上设置断点

### Requirement: 运行时 server 开发态可调试

开发模式下，运行时 server 进程 SHALL 开放一个调试端口，使外部调试器（编辑器或浏览器）可 attach 并在服务端代码上命中断点；开发模式下运行时监听端口 SHALL 为固定值，以便开发者直接对其 HTTP/SSE 接口进行手工测试。生产态下运行时 MUST NOT 开放调试端口，且监听端口保持既有的随机分配与仅本机可达约束。

#### Scenario: 服务端可 attach 断点

- **WHEN** 开发模式运行中，开发者用调试器 attach 到运行时 server 的调试端口，并在服务端代码路径设置断点
- **THEN** 相应服务端代码被执行时命中该断点

#### Scenario: 生产态不开放调试端口

- **WHEN** 非开发模式运行
- **THEN** 运行时 server 不开放任何调试端口，监听端口仍为随机分配且仅本机可达

### Requirement: 主进程开发态可调试

开发模式下，应用主进程 SHALL 以可被外部调试器 attach 的方式启动，使开发者能在主进程代码上设置并命中断点。生产态下主进程 MUST NOT 开放调试端口。

#### Scenario: 主进程可 attach 断点

- **WHEN** 开发模式运行中，开发者 attach 到主进程调试端口并在主进程代码设置断点
- **THEN** 相应主进程代码被执行时命中该断点

### Requirement: 一键开发启动与自动重启

系统 SHALL 提供单条开发启动命令，一次性并行拉起：渲染层开发服务、主进程与运行时源码的增量监视重建、以及在其产物变化时对应用的自动重启。当主进程或运行时源码发生改动时，系统 SHALL 自动重建并重启相关进程，无需开发者手动执行重建或重启。

#### Scenario: 单命令启动开发环境

- **WHEN** 开发者执行开发启动命令
- **THEN** 渲染层开发服务、主/运行时的监视重建、以及应用进程被一次性启动，进入可开发、可调试、可热更的状态

#### Scenario: 主/运行时改动自动重启

- **WHEN** 开发模式运行中，开发者修改并保存主进程或运行时的源文件
- **THEN** 系统自动增量重建并重启相关进程，使改动生效，无需手动干预

### Requirement: 编辑器一键调试配置

项目 SHALL 提供编辑器调试启动配置，使开发者可在编辑器内一键启动开发模式，并 attach 到主进程与运行时 server 两个进程进行断点调试。

#### Scenario: 一键启动并附加调试器

- **WHEN** 开发者在编辑器中运行提供的调试配置
- **THEN** 应用以开发模式启动，且调试器 attach 到主进程与运行时 server，二者均可命中断点
